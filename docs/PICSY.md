# PICSY研究モジュール — 数理的定義・責任分界

## なぜZokuZokuと親和性があるのか

商品が「Aの原作 → Bの改良 → Cの需要の発見」を経て生まれるとき、価値創出を最後の販売者だけに帰属させると原作・引用・改良が見えなくなる。ZokuZokuは**創作の有向グラフ**を持ち、PICSYは**価値を他者へ配分する評価の有向グラフ**を持つ。これらを関連づけることで直接の売上帰属だけでは見えない上流の貢献を研究できる。

ただし両者は同一ではない。
- ZokuZokuの作品系譜の辺は「どの作品を引用したか」という**著作・来歴**の事実。
- PICSYの評価辺は「誰が誰をどれだけ評価したか」という**取引・評価**の値。
- 来歴の存在だけで無条件にPICSY評価を増減させる設計は未検証。権利者との契約・合意も別途必要。

## 原資料にある定義

ユーザー提供『PICSY のモデル』第4章、4.1・4.2・4.5節を根拠に記述。

1. 評価行列 `E` は非負、各行の総和は1。
2. `E_ii` は参加者`i`の予算制約。
3. 仮想中央銀行法では `B=diag(E)`、`D=J-I` とすると `E′ = E − B + BD/(N−1)`。
4. `c E′ = c` かつ `Σc=N` を満たす貢献度ベクトルを計算する。
5. 買い手`b`が売り手`s`から価値を受け取る取引の評価操作は `E_bb -= α`, `E_bs += α` (自己評価の予算内)。
6. 自然回収の演算は `E_(t+1)=(1−γ)E_t+γI` （自己評価法/仮想中央銀行法の回収）。

**実装は学術的サンプルであり、原著の経済システムの完全実装ではありません。** 動的取引市場、定価、カンパニー、メンバー出入り、購買力制約、対価処理、権利者分配などは実装していません。

## 3人の経済

```mermaid
flowchart LR
 A[A 原作者] -->|原作の価値を継承| B[B 二次創作者]
 B -->|派生商品を提案| C[C ファン]
 C -->|Bから価値を受け取る、評価C→Bが増える| B
 B -->|評価の継承関係| A
```

初期評価行列：

```text
         A     B     C
A      0.80  0.20  0.00
B      0.00  0.70  0.30
C      0.20  0.00  0.80
```

CがBへ`α=0.15`の評価を行うと、Cの予算制約は`0.80→0.65`、CからBへの評価は`0.00→0.15`。この例の仮定はサービスの規約や価格ではなく、動的モデルを説明するための入力例です。

`app/picsy.py`はE→E′を構築し、`cE′=c`の定常分布を求めます。0.5のlazy walk `c_next=(c+cE′)/2`を用い、N=2などの周期性を避けます。これは原著のE′を改変する操作ではなく、**同一の定常分布を数値計算する工夫**です。任意の既約性/一意性が保証されないEには収束保証がないため、実装は収束しなければ例外を返します。

## セキュリティ・経済モデル上の未解決事項

- 独立したIP・作家・ファンIDの真正性。架空取引・相互取引・SybilによりEを操作できる。
- PICSY評価は**円建ての売上・債権・利益分配・証券評価額ではない**。相互変換の価格設定も未定義。
- 原作者へのロイヤリティは別途契約と支払台帳が必要。PICSYのcだけで自動的に支払う実装は存在しない。
- PICSYへの金銭的出資・投資・収益分配の実装は、法規制・投資家保護・税務を専門家と確認するまで禁止。
- 大規模ネットワークでのスパース行列・増分計算・誤差上界・検証可能な結果の記録が必要。
- 商品が複数原作品をマージしたときの貢献関係、原作撤回時の履歴・人格権・インセンティブが未定義。

## 数理テストの保証範囲

現在のテストは次を確認します。
- Eの各行の非負性と合計1の入力検査。
- E′の対角が0、行和が1。
- cの総和がN、`cE′≈c`。
- `E_bb`を超える取引の拒否。
- 取引および自然回収の行和保持。

市場操作耐性・均衡安定性・大量ノードへの性能は未検証です。

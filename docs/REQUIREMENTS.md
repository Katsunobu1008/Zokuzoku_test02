# ZOKUZOKU — 詳細実装要件定義 / Product Requirements & Acceptance

## 1. プロダクトスコープ

**事業コンセプト:** 「みんなの好きが『ゾクゾク』と。」。ファン同士でゾクゾクするグッズアイデアを生成・進化させ続け、思いがけない「欲しいっ！」を「続々」と発見・商品化する共創サービス。

「売れる商品は初めから計画できない」を出発点に、ひとつの最適商品を選ぶよりも、予想外の派生を探索する。ただし生産に進める判断では権利・需要・採算を確認する。

### ユーザー価値
1. **発見:** 自分では想像していなかったグッズに出会う。
2. **表現:** デザイン経験がなくても自分の好きに近づける。
3. **共創:** 他人のアイデアを引用し、次のファンへ継承できる。
4. **参加:** 作らない人も好きなアイデアに反応・応援できる。
5. **機会:** 権利者との契約と審査を経て商品化や収益分配に関与する可能性がある（未実装）。

### 事業価値の仮説
- A: 既存ECにない商品候補を発見する。
- B: 単独AI生成より共同創作が新しい需要を発見する。
- C: 意思表示や実予約による事前評価が、販売予測と増分利益の改善につながる。
- D: ファン参加の熱量と丸井Gの実商品化能力をつなぎ、継続的な共創基盤になる。

## 2. ペルソナ / ジョブ

| ロール | ジョブ | このMVPの実装 |
|---|---|---|
| 探索するファン | 欲しいけれど言語化できなかったグッズを見つけたい | 100世代系譜、ランダム発見、検索 |
| 創作するファン | 好きな要素を商品として表現したい | 作品投稿、任意のAI画像生成 |
| 改良するファン | 他者の着想を受け、自分なりの価値を加えたい | 親IDによる継承と表示 |
| 応援するファン | デザインスキルなくアイデアを支持したい | LIKE、コメント、架空ポイント意思表明 |
| 商品企画担当 | 未充足需要の仮説、商品化対象を見極めたい | 傾向集計（研究用、サンプル混在） |
| 権利者・メーカー | 権利を守りつつ多様なアイデアに出会いたい | 今後のIP許諾/商品化管理 |

## 4. 非機能要件

- **セキュリティ:** APIキーはサーバー側のみ。公開前にOIDC、セッション/CSRF、権利者の真正性、運用監査、秘密管理。
- **可用性:** 現MVPはローカル研究用でSLAなし。ベータ移行時にSLOを設計。
- **性能:** 初期100件で滑らかな探索体験。10,000件超はCanvasクワッドツリー/LOD/WebGL移行が必要。
- **一貫性:** 作品、LIKE、応援意思、イベントは単一DB内でトランザクション更新。
- **費用管理:** 画像生成はオプトイン、ローカル上限とOpenAI側の運用予算が必要。
- **移植性:** Python標準ライブラリとSQLiteでローカル起動。Dockerも用意。
- **プライバシー:** 実ユーザー受け入れ前に目的、利用期間、第三者提供、削除/開示、AI学習利用の扱いを明確化。
- **アクセシビリティ:** Canvasに依存しないカード一覧・キーボード移動・フォーカススタイル。厳密なWCAG検証は未実施。
- **国際化:** 現状日本語。UIラベルを資源ファイルへ切り出すのは将来。

## 5. Productization の意思決定ステート（将来）

```
DRAFT → PUBLISHED → INTEREST_VALIDATED → RIGHTS_REVIEW →
   PRICE_ESTIMATED → FUNDING/RESERVATION → APPROVED →
   MANUFACTURING → SALES → SETTLEMENT → REPORTING
```

各遷移に必要な入力は、責任者、契約文書、商品仕様、原価、納期、品質基準、予約引当、取消・返金規程、利益計算ルール。著作権者許諾とユーザー創作物の利用許諾は別々に記録。

## 6. 実験設計と成功判定

**主要指標:** 「体験前に買うつもりのなかった商品を、価格提示後に実際に購入した人 / 全参加者」。実購買前の購入意思は代理指標であり分離する。

| 実験群 | ユーザーの体験 | 何を分離するか |
|---|---|---|
| A | 従来商品を見る・選ぶ | 基準値 |
| B | 自分でAI商品画像を生成 | 生成機能そのものの効果 |
| C | 他者の派生作品に出会い、継承・改良 | **共創の純増価値 C−B** |

共創群は互いの作品が影響するので、個人を単純無作為化するだけでは独立性が損なわれる可能性がある。コミュニティ単位でクラスター割付を検討する。IPカテゴリ・価格・利用時間等を統制。主要仮説・評価指標・目標サンプル数は実験前に事前登録。

**企業利益:** 新規売上－製造変動費－IP/作者ロイヤリティ－画像生成費－開発運営費－顧客獲得費－既存商品カニバリゼーション。ポイント支持やLikeは利益として計上しない。

## 7. リリースゲート

1. **研究用デモ:** 現在。ローカル、架空IP、無償の応援意思、PICSY研究計算。
2. **招待制クローズドテスト:** 権利者合意、OIDC、監査、ログ、削除要求対応、モデレーション、予算管理、データ保護。
3. **商品化パイロット:** 製造・品質・権利・契約、予約時点の実料金表示、返品/キャンセル、利益検証。
4. **PICSYの実経済化:** 単なるポイント開発ではなく、学術/法務/会計/セキュリティ/金融リスク/シビル攻撃を独立評価し、事前の承認を得る。

## 8. 仕様から外したものを明確にする

- 人気があるほど「商品化権」が自動で確定する仕組みはない。審査/契約が必要。
- 応援ポイントから現実のエポスポイントを引き落とさない。
- PICSYを使えば法定通貨が自動増殖する/利益が保証されるという主張はしない。
- 生成モデルのコンテンツが第三者IP利用に適法である保証はない。
- サンプルの人気ランキングはビジネス上の購買需要を証明しない。
